# bursthttp v0.1.6 — Connection inspector, traffic shaping

**Release date:** 2026-05-03

### Install

```bash
go get github.com/muxover/bursthttp@v0.1.6
```

---

## Summary

Two features for observability and traffic control. The connection inspector gives you a live snapshot of every pooled connection — latency, health score, in-flight count, and byte totals — without any external tooling. The token-bucket rate limiter lets you cap outgoing RPS at the client level: callers block until a token is available, and context cancellation always unblocks immediately.

---

## What's included

### Connection inspector

- **`Client.ConnectionPool() []ConnectionInfo`** — returns one `ConnectionInfo` per live connection across all host pools. Fields: `ID`, `Host`, `Port`, `Healthy`, `ActiveReqs`, `HealthScore` (0–100), `LatencyEWMA`, `PipelineDepth`, `BytesRead`, `BytesWritten`.
- Per-connection byte counters are maintained atomically in both sequential and pipelined request paths.
- No locking on the read path — uses the same lock-free `atomic.Pointer` already used by the pool.

### Token-bucket rate limiter

- Set `Config.RequestsPerSecond` and `Config.BurstSize` (both > 0) to enable.
- `DoWithContext` blocks at the top of the request loop until a token is available.
- Three strategies: instant pass when tokens remain; sleep the exact fractional-token wait time; unblock immediately on `ctx.Done()`.
- Works alongside adaptive retry and the scheduler — rate limiting applies per client instance, not per host.
